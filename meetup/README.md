# Meetup Profiles Scraper

Fetches the attendee list for a Meetup event and enriches each profile with bio, location, and social network links via Meetup's internal GraphQL API. Also cross-checks attendees against Google (via Serper.dev) to find likely LinkedIn profiles, and builds a local searchable viewer.

## What it does

1. **Fetches all RSVPs** for a given Meetup event (paginated)
2. **Enriches each member** with sidebar profile data: city, country, bio, social networks (LinkedIn, Instagram, Twitter), job field, and member since date
3. **Cross-checks name + city against Google** to find a likely LinkedIn profile URL, with a confidence score
4. **Builds a local viewer** (`meetup_viewer.html`) — searchable/sortable table, no server-side deps beyond a static file host

## Architecture

```
meetup-request.txt           # Raw browser request captured from DevTools (headers + payload)
meetup-member-info.txt       # Raw browser request for the member sidebar query

meetup_request.py            # Step 1 — fetches all event attendees (paginated)
                             #   → output: meetup_response.json

meetup_member_info.py        # Step 2 — enriches each member with profile details
                             #   → reads:  meetup_response.json
                             #   → output: meetup_members_details.json

find_linkedin.py             # Step 3 — cross-checks name + city against Google (Serper.dev)
                             #   → reads:  meetup_members_details.json
                             #   → output: meetup_linkedin_matches.csv
                             #   → requires SERPER_API_KEY in Meetup/.env (see .env.example)

build_viewer.py              # Step 4 — builds the local searchable/sortable viewer
                             #   → reads:  meetup_members_details.json
                             #   → output: meetup_viewer.html
                             #   → serve with: python3 -m http.server 8765

meetup_response.json         # Raw attendee list (all RSVP statuses)
meetup_members_details.json  # Enriched member profiles
meetup_linkedin_matches.csv  # Best-guess LinkedIn URL per attendee + confidence (high/medium/low/no match)
meetup_viewer.html           # Generated by build_viewer.py — do not hand-edit, re-run the script instead
```

## How it works

Both scripts call `https://www.meetup.com/gql2`, Meetup's internal GraphQL endpoint, using **Apollo Persisted Queries** — a SHA-256 hash identifies the query server-side, so no query string is needed.

**Step 1 — `meetup_request.py`**
- Operation: `getEventByIdForAttendees`
- Paginates using cursor-based navigation (`after` + `endCursor`) until `hasNextPage` is false
- Filters RSVPs by status: `YES`, `ATTENDED`, `NO_SHOW`, `EXCUSED_ABSENCE`

**Step 2 — `meetup_member_info.py`**
- Operation: `getSidebarInfo`
- Loops through all member IDs from `meetup_response.json`
- Requires an authenticated session (auth token cookie) to access profile data
- Adds a 300ms delay between requests to avoid rate limiting

**Step 3 — `find_linkedin.py`**
- Queries Google via Serper.dev (`https://google.serper.dev/search`) with `site:linkedin.com/in "{name}" {city} (figma OR designer)`
- Skips single-word names (e.g. "Figs", "MH") — too generic to search reliably, marked `skipped` in the output
- Takes the top `linkedin.com/in` result and scores confidence by how many name tokens appear in the result title (`high` = all tokens match, `medium` = ≥half, `low` = less)
- **Always manually review before trusting a match** — common names produce false positives; this is a starting point, not a confirmed identity
- Cheapest approach for this volume: Serper.dev free tier covers 2,500 queries, so 51 lookups cost effectively $0. Free unofficial Google-scraping libraries were considered but rejected — they get CAPTCHA-blocked/rate-limited too often to be reliable.

**Step 4 — `build_viewer.py`**
- Reads `meetup_members_details.json`, embeds it directly as a JS array in the generated HTML (no backend, no build step)
- Regenerate after re-running Step 2 by re-running this script — don't hand-edit `meetup_viewer.html`, changes will be overwritten
- Serve locally rather than opening as `file://` (browsers can be inconsistent with local JS on file:// depending on settings): `python3 -m http.server 8765` from this folder, then open `http://localhost:8765/meetup_viewer.html`

## Local viewer setup

`meetup_viewer.html` is a static file — all data is embedded in it, no backend required. It's served locally instead of opened via `file://` because some browsers restrict local JS execution depending on settings.

**Start the server** (from the `Meetup/` folder):
```
python3 -m http.server 8765
```
Then open **http://localhost:8765/meetup_viewer.html**.

**Run it in the background** so it keeps serving after you close the terminal:
```
nohup python3 -m http.server 8765 > /tmp/meetup_viewer_server.log 2>&1 &
```

**Check if port 8765 is already in use:**
```
lsof -i :8765 -sTCP:LISTEN
```

**Stop the server:**
```
kill $(lsof -t -i :8765)
```

**After re-running Step 2 or Step 3** (new attendee data or new LinkedIn matches), re-run `python3 build_viewer.py` to regenerate the HTML — the running server picks up the new file on next refresh, no restart needed. Port 8765 is just a convention used here, not a fixed requirement — any free local port works.

## Output fields (`meetup_members_details.json`)

| Field | Description |
|---|---|
| `id` | Meetup member ID |
| `name` | Display name |
| `email` | Email address (returned empty by Meetup even when authenticated) |
| `city` | City |
| `country` | Country code |
| `bio` | Profile bio |
| `social_networks` | List of linked accounts (LinkedIn, Instagram, Twitter) with URLs |
| `job_field` | Job field if set |
| `member_since` | Account creation date |
| `events_attended` | Total RSVPs count |

## Authentication

`meetup_request.py` works without authentication (public event data).  
`meetup_member_info.py` requires the `__meetup_auth_access_token` cookie (and session cookies) from an active Meetup browser session. Update the `cookie` field in the headers with a fresh token when it expires.  
`find_linkedin.py` requires `SERPER_API_KEY` in `Meetup/.env` — sign up free at [serper.dev](https://serper.dev) (2,500 free queries, no card required). See `.env.example` for the expected format. `.env` is gitignored at the repo root, safe to keep the real key there.
